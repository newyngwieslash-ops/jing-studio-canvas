# 架构与技术原理

影策（晶电影工作室）由浏览器创作工作台、Go 业务后端、Node Pi Agent 执行层及持久化基础设施组成。无限画布编辑、异步模型生成、Pi Agent 推理与批量生成、短剧自动化制作、电商五步策划以及方舟素材库认证是互相协作的业务流，但各自拥有独立的状态机、授权边界和完成判据。

本组文档基于当前代码树实际源码与配置阅读，解释真实控制流与数据合同；不将设计提案、工作约定或测试文件的存在等同于已经上线并通过生产验收。本次仅梳理与更新文档及架构图，未修改业务实现代码。

这里不把后端内部的 `service`、`app`、`repository` 或各领域包画成独立微服务：它们运行在同一个 Go 进程内，通过包边界隔离依赖。独立 `yingce-agent` 容器与宿主机 `Host Updater`（Unix Socket）才是真正的跨进程/网络边界；本地开发未设置 `YINGCE_AGENT_URL` 时的 embedded 模式同样是由 Go 启动的本地 Node 子进程。

## 4. 六条核心技术链

### 4.1 用户操作、账号隔离与实时协作

`页面交互 → 页面局部 State/Ref 或 Zustand Store → 带用户 Scope 的 localforage 快照 & Mutation Journal → HTTP API / WebSocket → 服务端归属与版本校验 → 数据库`。

高频指针拖拽、稳定画布快照、React Query 查询缓存与 WebSocket 实时光标（`canvas-presence-renderer.ts` 直接复用 DOM，不经过 React 重渲染）分属不同通道。账号切换必须先暂停生成结果消费者、在同步独占区内 flush 旧 scope 并清理 Blob/Query 缓存，再切换 scope 与 session generation，防止跨账号串数据。详见 [前端架构](./frontend.mdx)。

### 4.2 模型生成、声明式协议与结果交付

`生成意图 → CreateTask 准入（冻结逻辑模型路由、归一思考等级、校验参考图/视频与方舟素材授权、预留积分与存储配额） → Task 落库 → Worker 领全局槽与 45s 任务租约 → 声明式/内建 Provider 调用或异步回查 → 媒体回存 → taskLeaseWriter 条件写终态 → 前端 Effect 租约物化上画布`。

数据库 `Task` 表是持久控制面，Redis 负责跨实例槽位、限流与熔断。上游返回成功、平台回存 `Resource` 就绪、Task 终态提交、前端节点附着与账单结算各自存在独立失败窗口：媒体下载或写存储失败会写入加密 `MediaRecoveryJSON` 检查点，后续走“重试保存”而非重新付费生成。详见 [后端与任务](./backend.mdx)。

### 4.3 云端 Agent 推理、审批续跑与批量生成

`用户消息 → Go 创建/恢复 Run → Node Pi 会话 → POST /model 走平台文本任务 → POST /tool 查 29 项工具策略 → 需审批时写 waiting_approval 并向 Node 返回 pause 结束进程 → 用户批准后 Go 执行单条或批量生成（支持首条 Canary 试跑） → 携带持久回执重启恢复 Pi`。

Agent 的画布修改会生成带前后哈希的 `canvas_updated.undo` 撤销凭据；长期记忆通过 `memory_update` 维护版本化的用户记忆文档（Schema 76，`auto` 直接生效或 `review` 待确认）。远程 `yingce-agent` 调用失败绝不回退本地 embedded，避免已执行工具副作用被重复触发。详见 [Agent 与部署](./agent-and-deployment.mdx)。

### 4.4 短剧自动化制作与分池调度

`章节原文/剧本/分镜导入 → 作品圣经（bible）与分批拆集（plan） → 镜头脚本与台词核对 → 按模型能力与单段目标时长（4–15s）切分 DramaSegment → 段提示词（可挂载单轮写作技能） → 样片/每集审阅与媒体放行 → 段视频生成与循环外后台尾帧抽取 → 时间线成片合成与剪映草稿导出`。

`DramaJob` 表达业务步骤，派发时才创建通用 `Task`。调度器按文字（`text`）、参考图（`image`）、段视频（`video`）、成片（`render`）四个独立并发池统计在途数，按“先集号、同集内成片 > 剧本 > 提示词 > 视频”排序派发；耗时的尾帧下载与 ffmpeg 抽帧交由 `drama_tail_worker.go` 在主循环外异步完成。详见 [短剧制作](./production.mdx)。

### 4.5 电商 Agent 五步策划与行业知识库

`商品图与资料输入 → 识图理解与卖点提取 → 行业分类祖先匹配离线知识包（ecommerceknowledge）与平台排版安全规范（platform_knowledge.json） → 风格方向推荐 → 逐屏策划方案审阅 → 批量提交通用生成任务出图/出片`。

电商策划与识图阶段使用的模型及思考等级由后台 `EcommerceAgentSetting` 权威绑定，`CreateTask` 准入时校验客户端提交是否与后台阶段模型一致并强制覆盖 `thinkingLevel`，防止绕过管理员配置。详见 [Agent 与部署](./agent-and-deployment.mdx#6-电商-agent-与行业知识库架构)。

### 4.6 资源身份、方舟素材库与分级分发

`Resource 稳定身份 / 方舟 asset:// 认证素材 / 姿势库模板 → 归属、有效期与场景授权校验 → 派生平台代理、源站或 CDN 临时签名 URL → 浏览器展示或上游模型拉取`。

长期业务数据只保存 `resourceId` 或受管 `asset://` 引用，不把短期签名 URL 当作持久化主键。素材删除通过事务写入 `ResourceDeletionJob` Outbox，由后台 Worker 幂等清理物理对象。详见 [后端与任务](./backend.mdx#9-资源身份访问交付与方舟姿势库)。

## 5. 数据所有权与一致性

| 数据域 | 权威来源 | 其他副本或投影 | 关键一致性规则 |
| --- | --- | --- | --- |
| 账号、权限与配额 | 服务端会话、用户组、存储配额与资源归属校验 | 前端路由守卫、按钮显隐 | 前端守卫仅用于体验，所有读写删均在 `app`/领域层按 `userID` 强校验 |
| 画布编辑与实时状态 | 服务端已确认 `revision` + 本地未确认 mutation journal | `localforage` 快照、WebSocket 临时光标与拖拽框 | 实时 Presence 不落库；Agent patch 必须满足 `revision = baseRevision + 1` |
| 生成任务与文本流 | 数据库 `Task`/`TaskResult`、租约 owner 与 `TaskTextDelta` | React Query 缓存、SSE 增量流 | 每次执行后写回均经 `taskLeaseWriter` 校验当前租约；SSE 断开不等于取消任务 |
| 模型媒体产物 | `Resource` 表状态（`pending/ready/failed`）与底层存储对象 | 播放转码副本、CDN 缓存、浏览器 Blob 缓存 | 上游生成成功与平台落盘分开记录；落盘失败保留 `MediaRecoveryJSON` 供重试保存 |
| 云端 Agent 与记忆 | `CloudAgentRun`、审批记录、`SessionJSONL`、`Checkpoint`、`AgentMemoryDocument` | 聊天面板消息、本机发送队列 outbox | `SessionJSONL` 绑定 `expectedRevision` 条件更新；`Checkpoint` 严格限制 64 KiB 且历史视为不可信数据 |
| 短剧制作 | `DramaProduction`、`DramaCast`、`DramaEpisode`、`DramaShot`、`DramaSegment`、`DramaJob`、`DramaTake` | 制作台视图、精修画布节点、时间线渲染计划 | 制作花费按计费订单（含流水线与精修画布）汇总；精修画布产物须显式采用才写回短剧 |
| 电商工作区 | `EcommerceProject`（`revision`、`Draft`、`Plan`）、离线知识包与行业分类树 | 浏览器五步工作区草稿、同商品历史记录 | 保存校验 `revision`；识图与策划阶段模型及思考等级由服务端后台配置强制约束 |
| 积分与计费 | 预留记录、计费订单（含 Token 分时/上下文档位与参考视频快照）、结算/待核对账单 | 前端报价估算与钱包展示 | 明确未发出的失败可自动退回预留；上游状态不明的请求进入账单核对，不盲目退款或重发 |

## 6. 已核实的约定与实现差异

以下差异来自源码逐行核对，供开发与排障参考：

| 常见印象或历史描述 | 当前代码真实实现 |
| --- | --- |
| Redis 是持久化任务队列 | 数据库 `Task` 表与租约字段驱动调度；Redis 承担全局并发槽、限流、熔断、路由健康与画布实时房间广播 |
| `internal/service` 包含独立业务逻辑 | `internal/service` 是 `internal/app` 的类型与函数别名稳定导出层（`aliases_*.go`），组合根在 `internal/app` |
| 所有接口错误都已走 `failService` 保留 `AppError` | `POST /api/tasks` 在 `CreateTask` 返回错误时仍调用 `fail(c, http.StatusBadRequest, err)`（见 `handler/routes.go:49-51`） |
| 任何被画布或任务引用的素材都无法删除 | 普通非归档删除会拦截引用并返回占用来源；但 `purge=true` 彻底删除及部分归档清理允许忽略任务/画布引用，且物理文件经 Outbox 异步删除 |
| 所有出站请求都彻底移除了私网全局放行开关 | 自定义渠道中转（`/api/ai/custom`）严格忽略全局开关，仅認精确白名单；普通上游出站仍读取遗留的 `CANVAS_ALLOW_PRIVATE_UPSTREAMS` |
| 编辑器已拆分为 8 个可独立安装的插件包 | 当前由单个内建 v2 插件 `editor-shell.tsx` 一次性注册 8 个编辑器插槽；且画布弹窗仍保留浏览器 `ffmpeg.wasm` 导出入口与后端渲染任务并存 |
| 短剧尾帧在 `tickDrama` 循环内同步下载抽取 | 已迁出主循环，由 `drama_tail_worker.go` 按视频资源加租约在后台异步抽取（单进程并发 4），主循环遇到抽取中仅标记 `dramaPendingTail` |
| `docs/` 下包含可运行的 Next.js 文档站工程 | 当前仓库仅保留 `docs/content/docs/` 下的 MDX 源文档、`docs/design/` 与 `docs/architecture/`，无 `docs/package.json` 或 `docs/source.config.ts` |

## 7. 维护与验证纪律

修改架构、任务协议、数据库表或 Agent 工具链时：

1. 先核对真实入口、调用方、事务边界与相邻测试，同步更新本目录下的对应专题文档及 [代码功能地图](../backend/code-map.mdx)、[HTTP API 合同](../backend/http-api.mdx) 或 [后端数据库](../backend/backend-database.mdx)。
2. 若拓扑或时序发生变化，更新 `docs/architecture/diagrams/` 下的 `.json` 或 `.archify.md` 规格，使用 Archify 3.2 `finalize` 重新生成 HTML 与验证回执，切勿手工编辑生成的 HTML。
3. 推送前在仓库根目录运行 `bun scripts/verify-before-push.mjs` 完成与改动范围匹配的本地并行检查；尚未在真实环境确认的改动写入 [待测试清单](../progress/pending-test.mdx)。
