# 短剧制作领域与持续编排

影策的短剧制作不是在浏览器里按顺序串行调用几个接口的临时脚本，而是以数据库为持久真相源、由 Go 服务端后台调度器持续推进的领域状态机。**视频生成的最小调度与出片单位是 `DramaSegment`（剧情段）**，一个剧情段由同一场景下按模型时长能力与用户目标时长合并的多个镜头（`DramaShot`）组成。

## 1. 领域模型与事实归属

核心数据结构定义在 [`models_drama.go`](../../../../backend/internal/model/models_drama.go)：

| 领域实体 | 持久化内容 | 架构角色与关系 |
| --- | --- | --- |
| `ProjectUnit`（chapter） | 导入的小说章节、剧本或分镜原文 | 改编输入源，按游标分批读取 |
| `DramaProduction` | 制作状态、配置 JSON（含模型、画幅、并发、单段目标时长）、作品圣经、预算、已用积分、规划游标、暂停原因 | 以 `ProjectID` 为主键的全剧唯一控制面 |
| `DramaCast` | 角色/场景/道具设定、别名、外貌描述（支持差异化重写）、声线、参考图资源 ID、锁定状态与 `revision` | 跨集共享视觉锚点，锁定后全剧复用同一形象 |
| `DramaEpisode` | 集号、章节范围、来源格式（`novel`/`script`/`storyboard`）、阶段、提示词批准、媒体放行、成片资源与 `FinalStale` 标记 | 单集制作生命周期载体 |
| `DramaShot` | 镜号、景别、运镜、时长、台词（支持原文逐句核对）、动作、出镜设定引用、所属 `SegmentIndex` | 剧本与分镜颗粒度，不直接绑定单独的视频生成任务 |
| `DramaSegment` | 汇总提示词、人工覆盖文本、模型覆盖、有序参考图列表、生成的段视频 `ResourceID`、实测时长与尾帧 `TailFrameResourceID` | **一次视频生成请求与尾帧连续性的权威单元** |
| `DramaJob` | 作业类型（`bible`/`plan`/`cast_image`/`script`/`segment_prompt`/`segment_video`/`render`）、优先级、关联 `TaskID`、历史 `AttemptsJSON` | 业务调度队列；派发时才创建通用 `Task`（注：段作业复用历史列 `ShotID` 存放 `SegmentID`） |
| `DramaTake` | 设定参考图、段视频或成片的历次生成/采用版本（含 `ResourceID`、`TaskID`、提示词与时长） | 版本回溯与精修画布写回记录 |

`DramaJob` 与通用 `Task` 分属两层：`DramaJob` 表达“短剧流水线缺哪一步”，通用 `Task` 负责“模型路由、租约执行、账单冻结结算与媒体落盘”。当短剧关联的 `Task` 进入终态时，`wakeDramaAfterTask` 会立即唤醒短剧调度器，无需傻等下一轮轮询。

## 2. 服务端调度循环、四类并发池与循环外尾帧抽取

### 2.1 `syncJobs → plan → dispatch` 单项目租约循环

[`drama_orchestrator.go`](../../../../backend/internal/app/drama_orchestrator.go) 的 `startDramaScheduler` 由唤醒通道与 3 秒 Ticker 驱动。每轮拉取最多 20 个运行中项目，通过协调器获取 `drama:<projectID>` 互斥租约（TTL 2 分钟）后执行 `tickDrama`：

1. **`syncJobs`（同步结果）**：遍历 `queued`/`running` 作业，回读通用 `Task` 状态与计费订单。即使作品已处于 `paused` 暂停态，仍会执行 `syncJobs` 将已发出的在途任务结果入库并触发尾帧抽取，避免丢失已付费产物。临时数据库读取错误只会延后到下轮重试，不会误判为任务丢失。
2. **`plan`（推导缺口）**：对照当前作品圣经、分集窗口（默认同时推进 6 集）、设定图、剧本、段提示词、段视频与成片状态，按幂等组合键补齐缺失的 `DramaJob`。
3. **`dispatch`（分池优先级派发）**：按优先级排序，在并发池容量、账号活跃任务上限与项目预算允许范围内调用 `CreateTask` 提交执行。

### 2.2 四类独立并发池与集号优先算法

[`drama_dispatch.go`](../../../../backend/internal/app/drama_dispatch.go) 将短剧作业划分为四个互不抢占的并发池：

- **文字池（`text`）**：作品圣经（`bible`）、分集规划（`plan`）、分镜剧本（`script`）、段视频提示词（`segment_prompt`）。
- **参考图池（`image`）**：角色、场景、道具设定图（`cast_image`）。
- **段视频池（`video`）**：剧情段视频生成（`segment_video`）。
- **成片合成池（`render`）**：单集时间线渲染（`render`）。

由于上游视频生成往往耗时数分钟，分池机制确保段视频排队不会堵死后续集的剧本撰写和设定图生成。池内及跨池共享账号配额时的派发优先级遵循：

- 作品级作业最高：`bible (30,000,000) > plan (20,000,000) > cast_image (10,100,000 - position)`。
- 单集级作业按 **集号越小越优先**（`(10000 - episodeNumber) * 1000 + rank`），同一集内按 `render (900) > script (800) > segment_prompt (700) > segment_video (300 - segmentIndex)` 排序，从而让第 1 集尽快跑通全流程出片，而不是所有集同时停在半成品阶段。
- `dramaDispatchWaits` 与派发逻辑同源计算每条排队作业的精确等待原因（如本池已满、前序段视频未完成、样片待批准等）并直接展示在制作台 UI。

### 2.3 循环外后台尾帧抽取（`drama_tail_worker.go`）

下载段视频、运行 `ffmpeg` 抽取最后一帧并上传存储可能耗时数十秒至数分钟。若放在 `tickDrama` 内同步执行，会拖慢整个调度循环。[`drama_tail_worker.go`](../../../../backend/internal/app/drama_tail_worker.go) 将其解耦到循环外后台 Worker：

- 当 `syncJobs` 发现段视频 `Task` 已成功且尚未提取尾帧时，调用 `startDramaTail(resourceID, work)` 异步启动抽帧，本轮返回 `dramaPendingTail` 使作业保持运行态。
- 后台 Worker 按视频 `resourceID` 去重，单进程最大并发 4（`dramaTailConcurrency = 4`），并通过协调器申请 `drama-tail:<resourceID>` 分布式租约（TTL 8 分钟）防止多实例重复抽帧。
- 抽帧落库成功后立即调用 `wakeDramaScheduler()` 唤醒主循环解锁下一段视频派发；若抽帧失败则暂存错误供下一轮 `takeDramaTailFailure` 读取并标记作业可重试（复用已有付费视频，不重跑视频生成）。

## 3. 从原文导入到分镜、单段目标时长与写作技能

### 3.1 圣经、拆集、角色外貌重写与台词核对

- **多格式导入**：`SourceFormat` 支持小说原文（`novel`）、剧本（`script`）与分镜表（`storyboard`，可经 `applyDirectStoryboard` 直接落库免模型改编）。长篇小说按 `PlanCursor`（每批最多 12 章或 30,000 字符）增量规划分集。
- **角色外貌差异化重写**：[`appearance_rewrite.go`](../../../../backend/internal/production/appearance_rewrite.go) 与 `app/drama_appearance.go` 支持对同剧角色组进行外貌特征差异化重写，减少多个角色出图撞脸；设定图生成时只清理画风规则中的冲突画幅词，原样保留设定细节。
- **原文台词逐句核对**：[`dialogue_check.go`](../../../../backend/internal/production/dialogue_check.go) 支持将分镜台词与章节原文对齐核查，并在 `drama_editing.go` 中支持持有调度租约安全地追加集、在指定集前后插集（自动平移集号 `shiftDramaEpisodeNumbers`）、删集及增删镜头。

### 3.2 按模型能力与单段目标时长（4–15 秒）切分剧情段

[`assignDramaSegments`](../../../../backend/internal/app/drama_orchestrator.go) 调用纯函数 `production.SegmentShotsForVideo` 将镜头序列切分为 `DramaSegment`：

- [`drama_models.go`](../../../../backend/internal/app/drama_models.go) 从模型目录读取当前视频模型支持的时长枚举、最大时长与参考图上限。
- 用户在新建短剧页（`create.tsx`）或制作设置中可指定**单段目标时长 `target_segment_seconds`（提供 4–15 秒快捷选择及自定义，0 表示跟随视频模型上限）**。切段算法综合场景边界、镜头累计时长与 `target_segment_seconds` 切分剧情段，并为每段生成包含景别、运镜、台词、声线与参考图编号的段提示词。
- 段提示词支持配置分阶段思考等级（`StageThinking`），若生成结果超出视频模型字符上限，会在同一作业内自动发起精简任务。

### 3.3 写作技能注入与非交互流水线兼容

资产提取（`bible`）、分镜拆分（`script`）与段提示词（`segment_prompt`）三个步骤支持挂载用户已安装技能包中的单个说明文件（按 `MaxWritingSkillRunes = 16000` 截断注入）。因为短剧调度是**服务端后台单轮非交互流水线**，若误选了面向多轮对话设计且带有“未回答前置问卷则停止输出”门禁的总控 `SKILL.md`，模型会返回空的 `characters` 或 `shots` JSON 数组。多文件技能套装应选用具体的非交互子规则文件，详见 [短剧制作写作技能兼容性排查与改进方案](../../../design/drama-writing-skill-compatibility.md)。

## 4. 审阅关口、订单级预算汇总与连续出片

### 4.1 样片关口、手动媒体放行与模型匹配

- **手动媒体与样片审阅**：开启手动媒体模式时，剧本与段提示词仍可先行生成供人工审校，参考图与段视频需显式放行（`AssetsReleased` / `Episode.MediaReleased`）才派发；开启样片审阅时，第 1 集批准（`SampleApproved`）前阻止后续集进入视频生成。
- **强制参考图模型保护**：若所选视频模型要求必须提供参考图，遇到无可用参考图的剧情段时，`prepareDramaSegment` 会在预演说明中提前拦截提示，默认模型选择也会自动避开此类强制限制模型。

### 4.2 尾帧续接模式 vs 并行出片模式

[`drama_segment_video.go`](../../../../backend/internal/app/drama_segment_video.go) 的 `prepareDramaSegment` 被前端预览与后端实际派发共用，确保预览看到的参考图顺序与实际发往模型的请求完全一致：

- **尾帧续接模式（默认）**：同集第 2 段起必须等待上一段视频生成完成且 `TailFrameResourceID` 抽取就绪，自动将上一段尾帧作为本段首帧参考，再合并本段出场角色/场景/道具参考图，实现镜头间画面连续。
- **并行出片模式**：各段不依赖上一段尾帧，只要本段提示词与设定参考图就绪即可并发派发，适合追求出片速度且段间无需严格首尾衔接的题材。

### 4.3 按计费订单汇总花费與成片合成

- **订单级花费口径**：[`repository/drama_billing.go`](../../../../backend/internal/repository/drama_billing.go) 与 `app/drama_billing.go` 按实际计费订单汇总短剧流水线任务与关联精修画布任务的实收及冻结积分；达到项目预算上限时自动暂停新派发（`dramaBudgetPauseReason`）。
- **时间线成片合成与剪映草稿导出**：
  - 全集段视频就绪后，`buildDramaTimeline` 按段视频实测时长（`media_probe.go`）拼接并提交后端 `ffmpeg` 渲染任务，按目标画幅自动裁切或补黑边（`renderSegmentFit`）并写入 AIGC 隐式元数据标识（`renderAIGCLabel`）。
  - [`internal/jianying/draft.go`](../../../../backend/internal/jianying/draft.go) 与 [`app/drama_export.go`](../../../../backend/internal/app/drama_export.go) 支持将单集或全剧资产包导出为可直接导入剪映专业版的草稿流式 ZIP 包，也支持从 ZIP 资产包恢复导入。

## 5. 精修画布双向投送闭环

[`drama_canvas.go`](../../../../backend/internal/app/drama_canvas.go) 与前端 `drama-canvas-projection.ts` 构成“短剧制作台为事实源、无限画布为精修台”的双向闭环：

1. **短剧投送到画布**：将角色设定、剧情段分镜与参考关系一键投送为画布节点与段分组框，复用稳定素材 ID `drama-<resourceID>`，不重复拷贝底层物理媒体文件；画布内生成的费用同样受短剧项目预算闸门（`ensureDramaCanvasBudget`）约束并计入总花费。
2. **画布显式采用回写**：在画布中重新抽卡生成的设定图或段视频不会静默篡改短剧；只有用户点击“采用”或通过 Agent 审批执行 `drama_adopt_canvas_media` 时，服务端才在事务内校验 `revision`、更新 `DramaCast`/`DramaSegment`、写入新 `DramaTake` 版本、标记旧成片 `FinalStale`，并在尾帧模式下自动触发新尾帧抽取与后续段可选级联重做。
