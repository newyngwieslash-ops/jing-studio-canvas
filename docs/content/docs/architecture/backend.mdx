# 后端、生成任务与资源一致性

本文依据当前代码树 `backend/` 的源码，梳理 Go 后端从进程启动、分层装配、任务准入（含思考等级映射、电商阶段模型绑定、视频 Token 与参考视频计费）、数据库租约调度、声明式模型协议宿主、文本 SSE 回放到资源签名交付及方舟素材库/姿势库的完整实现机制。

## 1. 启动、初始化与优雅停机

入口位于 [`cmd/server/main.go`](../../../../backend/cmd/server/main.go) 的 `main → run`：

1. 初始化结构化日志，建立监听 `SIGINT`/`SIGTERM` 的根 `context`。
2. 解析 `CANVAS_BACKEND_DATA_DIR`（代码默认值为 `data`，宿主机本地开发规范要求显式指定 `.local/project-workbench-debug`）、数据库驱动（`sqlite` 或 `postgres`）与连接串，执行 `database.Open` 与 `ConfigurePool`。
3. 当 `CANVAS_AUTO_MIGRATE=true` 时运行 `MigrateSchema`（当前已演进至 Schema 89+）；生产部署设为 `false`，由独立 `migrate` 容器先行迁移，主服务启动时通过 `RequireSchemaVersion` 校验版本。
4. 构造 `repository.New(db)` 与 `service.New(repo, dataDir)`；若配置了 `CANVAS_UPDATER_TOKEN`，注入 Unix Socket `updaterclient`，随后执行 `ValidateRuntime` 检查运行时前置依赖（如 PostgreSQL 模式下的 Redis 可用性）。
5. 依次幂等初始化核心系统目录：**系统渠道模型、默认用户组、提示词模板、内置电商知识包（`EnsureBundledEcommerceKnowledge` / `EnsureBuiltinEcommerceKnowledge`）、行业分类字典（`EnsureIndustryTaxonomyKnowledge`）、电商托管技能包、项目工作流模板、内置技能包、内置工具与工作台目录**。上述初始化任一失败即中止启动，防止升级后带着残缺目录对外提供服务。
6. 初始化 Gin 引擎、请求恢复、Trace/Request ID 注入、CORS 策略，注册 `/api` 业务路由、OAuth 回调、画布实时 WebSocket 及模型代理路由。
7. 成功监听 TCP 端口后，启动后台任务 Worker、短剧调度器、方舟素材审核/过期巡检 Worker、资源物理删除 Worker 及存量视频播放副本/尺寸回填任务。

**优雅停机顺序**：收到退出信号后先调用 `beginDrain` 拒绝新任务准入与新租约领取；HTTP Server 最多等待 30 秒完成在途请求，随后按 `CANVAS_SHUTDOWN_TIMEOUT`（默认 10 分钟）等待后台任务与 Pi Agent 会话保存完检查点后安全退出。

## 2. 包分层边界与统一响应合同

后端各包属于同一个 Go 二进制进程内的模块边界，而非拆分为多个微服务：

| 包路径 | 职责边界 | 核心源码入口 |
| --- | --- | --- |
| `cmd/server` | 进程生命周期、环境变量装配、启动自检与信号处理 | [`main.go`](../../../../backend/cmd/server/main.go) |
| `internal/handler` | 登录态提取、请求体大小与速率限制、参数绑定、统一 JSON/SSE/WebSocket 响应 | [`routes.go`](../../../../backend/internal/handler/routes.go)、[`response.go`](../../../../backend/internal/handler/response.go) |
| `internal/service` | 稳定导入面，仅通过类型与函数别名再导出 `internal/app` | [`doc.go`](../../../../backend/internal/service/doc.go)、[`aliases_funcs.go`](../../../../backend/internal/service/aliases_funcs.go) |
| `internal/app` | HTTP 组合根与跨域编排（任务准入、Worker、Provider 调度、短剧、电商、方舟、计费） | [`service.go`](../../../../backend/internal/app/service.go) |
| 独立业务域包 | `auth`、`canvas`、`skills`、`prompts`、`tools`、`workbench`、`poselibrary`、`production`、`ecommerceagent`、`ecommerceknowledge`、`ecommerceskills`、`ecommercecatalog`、`protocol`、`payment`、`sms`、`platform`、`assets`、`outbound`、`agentcontext` | 各领域包不得反向 `import internal/app` 或 `internal/service` |
| `internal/repository` | GORM 查询、条件更新、事务封装、数据库租约与账单汇总 | [`repository_tasks.go`](../../../../backend/internal/repository/repository_tasks.go)、[`finance_billing.go`](../../../../backend/internal/repository/finance_billing.go) |
| `internal/model` | 数据库表结构、状态枚举与纯值方法 | [`models_task.go`](../../../../backend/internal/model/models_task.go)、[`models_drama.go`](../../../../backend/internal/model/models_drama.go) |

### HTTP 响应信封与已知例外

`ok(c, data)` 返回 HTTP 200 与 `{ code: 0, data, msg: "ok" }`；`failService(c, err)` 将业务 `AppError` 投影为对应的 HTTP 状态码、业务 `code`、机器可读 `reason` 与脱敏消息，未知错误由 `failInternal` 隐去内部细节。

注意当前 [`handler/routes.go`](../../../../backend/internal/handler/routes.go) 的 `POST /api/tasks` 在 `svc.CreateTask` 返回错误时仍调用 `fail(c, http.StatusBadRequest, err)`，尚未改为 `failService(c, err)`，因此该入口的错误响应固定为 HTTP 400。

## 3. 生成任务准入（Admission）与计费冻结

[`task_creation.go`](../../../../backend/internal/app/task_creation.go) 的 `CreateTask` 是所有常规模型生成任务的唯一写入口：

1. **防伪造与排空拦截**：公共 `/api/tasks` 请求严禁携带内部 `admission` 或伪装 `cloud_agent` 操作；系统排空（Draining）期间返回 503 `Retryable: true`。
2. **电商阶段模型与思考等级强制绑定**：若任务标记 `metadata.source == "ecommerce-agent"`，服务端读取后台 `EcommerceAgentSetting` 强校验策划（`planning`）或识图（`product-understanding` / `creative-directions`）模型是否与管理员配置一致，并用后台配置的思考意图覆盖 `textOptions.thinkingLevel`，不信任客户端传参。
3. **统一思考等级映射（Thinking Level）**：[`provider.go`](../../../../backend/internal/app/provider.go) 与文本协议模块支持 `off/minimal/low/medium/high/max` 及意图 `auto/deep`，结合模型能力声明与协议默认规则（如保留旧版 Claude 默认关闭思考、尊重模型显式声明）归一为上游协议字段，并为画布 Agent 单步设置 `MaxOutputTokens` 防止思考耗尽全部输出预算。
4. **受管逻辑模型路由冻结**：服务端按模型目录、用户组可见性与功能开关解析渠道，在任务入库时冻结 `LogicalModelID`、`Revision`、目标渠道、协议格式、价格档位与 `RouteRun`。客户端无法篡改协议地址或价格。
5. **媒体引用与方舟素材校验**：拒绝内嵌大体积 `data:` URL；校验参考图/参考视频/音频的 `Resource` 归属，并由 `validateArkPortraitReferences` 校验 `asset://` 方舟素材是否属于本人、已授权平台组且未过期。
6. **视频 Token 计费与参考视频计费（Schema 88–89）**：
   - [`video_token_billing.go`](../../../../backend/internal/app/video_token_billing.go) 支持按分辨率像素、帧率与时长估算视频 Token 用量，结算时按上游返回的可信用量退补差额。
   - 支持渠道模型开启“参考视频计费开关”并配置独立的“带参考视频售价与成本价”；切换重试线路时保留参考视频计费快照，且视频后处理任务的源视频不误计为参考视频。
   - 文本模型支持分时与上下文区间阶梯价（`model/token_price_rules.go`），下单时冻结 `tokenPriceRuleSnapshot`。
7. **存储配额、并发上限与积分预留**：在 `createTaskWithinStorageQuota` 与数据库事务中原子完成活跃任务数检查、积分预留（Reservation）与敏感字段加密（`protectTaskSecrets`），入库后立即 `wakeTaskDispatcher()`。

此外，`text_replay` 任务仅作为前端流式存档容器或 Pi Agent 根任务控制面载体，不进入普通 Worker 消费队列，也不直接产生普通模型账单。

## 4. 数据库队列、双层租约与 Fencing 写保护

[`task_worker.go`](../../../../backend/internal/app/task_worker.go) 的 `taskWorkerCoordinator` 采用“进程内唤醒通道 + 2 秒周期扫描”双驱动，任务真相源始终在 SQL 数据库：

1. **全局并发槽租约**：先向协调器申请 `workers` 全局槽租约（TTL 1 分钟），受后台 `WorkerConcurrency` 限制。
2. **数据库任务行租约**：调用 [`ClaimNextTask`](../../../../backend/internal/repository/repository_tasks.go)（TTL 45 秒），以全局槽的唯一 `Token()` 作为 `lease_owner`。查询条件覆盖 `status = 'queued'` 或 `status = 'running' AND lease_expires_at <= now` 且 `next_poll_at <= now` 的任务；PostgreSQL 使用 `FOR UPDATE SKIP LOCKED` 跳过竞争行，SQLite 使用事务内条件更新。
3. **双层心跳续期**：执行期间每 15 秒同时续期全局槽与数据库 `RenewTaskLease`；一旦续租失败立即 cancel 当前任务的执行 `context`。
4. **Fencing 写保护（`taskLeaseWriter`）**：所有进度更新、Provider 状态记录与终态落库都必须匹配当前 `lease_owner` 且 `lease_expires_at > now`。即使旧进程因 GC 或网络卡顿在租约过期后醒来，其迟到写入也会因 `RowsAffected == 0` 被数据库拒绝，绝不覆盖新执行者结果。

## 5. 声明式协议插件宿主、异步回查与媒体恢复

[`processClaimedTask`](../../../../backend/internal/app/task_worker.go) 按任务类型分流：

- **本地专用执行器**：时间线字幕转写（本地 `whisper.cpp`）与时间线视频合成（`ffmpeg` 滤镜图）先于通用模型路由分叉执行。
- **媒体回存恢复（`MediaRecoveryJSON`）**：若任务已记录上游生成成功的作品地址但前次下载/写盘失败，Worker 直接进入 [`task_media_recovery.go`](../../../../backend/internal/app/task_media_recovery.go) 重新拉取并落盘，**不会重新调用上游模型重复扣费**。
- **声明式协议插件与内建 Provider**：
  - [`internal/protocol/`](../../../../backend/internal/protocol/manifest.go) 与 [`app/text_wire.go`](../../../../backend/internal/app/text_wire.go)、[`app/system_proxy_protocol.go`](../../../../backend/internal/app/system_proxy_protocol.go) 支持通过插件 `manifest.json` 声明 `TextWire`、`AgentWire`、`Auth`（含 `SecretKey` 双密钥鉴权）、参考图/视频组块方式（渠道默认与模型覆盖的 URL 或 Base64 发送）以及流式解析规则。
  - 流式响应若缺少明确的结束标记（如 `[DONE]` 或协议完成事件），不再误判为成功（防止截断输出被当作完整结果入库）。
  - 异步图片/视频任务提交上游后，若返回任务单号但尚未出片，调用 `DeferRunningTaskForProviderPoll` 记录 `ProviderRequestID`、`PollStage` 与 `NextPollAt`，释放当前 Worker 槽位；到期后再次被 `ClaimNextTask` 领回续查。当上游状态变为完成后，若媒体地址或 JSON 结果清单暂时为空，宿主在有界等待上限内继续轮询直至拿到媒体地址。

## 6. 取消、重试与账单对账收尾

[`task_lifecycle.go`](../../../../backend/internal/app/task_lifecycle.go) 与 [`task_terminal.go`](../../../../backend/internal/app/task_terminal.go) 维护严格的状态转移与资金安全：

- **用户取消边界**：任务一旦进入上游已提交/生成阶段，普通用户取消请求会被拒绝，防止用户白嫖已触发上游计费的结果；内部父任务取消或系统级中断则进入后台上游撤单与账单对账流程（`startProviderCancellationReconciliation`）。
- **终态结算与待核账单**：明确在发往上游前失败的任务直接释放积分预留；已向外部发出请求但因网络超时等原因结果不明的任务，进入 `startBillingReviewAudit` 账单核对队列，不盲目自动退款。
- **结构化执行诊断**：`TaskExecutionDiagnostic` 独立记录执行阶段、上游提交证据、恢复类别与写回状态，供前端与 Agent 精确判断。

## 7. 文本 SSE 增量持久化与有界回放

[`task_text_stream.go`](../../../../backend/internal/app/task_text_stream.go) 按约 2 KiB 或 500 ms 批量将模型流式增量写入 `TaskTextDelta`（含递增 `Sequence` 与过期时间）。若增量落库失败，仅降级关闭该次实时流发布，不中断模型主任务执行。

`GET /api/tasks/:id/text-events` 提供断线可续传的 SSE 流：

- 游标取 `?after=` 与 `Last-Event-ID` 中的较大非负整数（对应增量 `Sequence`，而非任务 ID）。
- 每 750 ms 从带缓存的回放层（`text_replay_cache.go`）读取新增片段推送 `delta` 事件，每 15 秒发送心跳注释，终态发送 `terminal` 快照。

## 8. 数据库、Redis 协调与画布实时房间

- **SQLite / PostgreSQL**：[`database.go`](../../../../backend/internal/database/database.go) 为 SQLite 默认开启 WAL、外键约束、`busy_timeout` 与 `IMMEDIATE` 事务锁；PostgreSQL 模式下强制要求配置 `REDIS_URL`。
- **Redis 协调层**：[`platform/coordination.go`](../../../../backend/internal/platform/coordination.go) 用 Redis 实现固定窗口限流、带租期的并发槽、渠道健康熔断与模型目录版本广播。
- **画布实时通知**：[`repository/canvas_change_notifications.go`](../../../../backend/internal/repository/canvas_change_notifications.go) 在数据库外层事务成功提交后合并发布画布变更通知（事务回滚则自动丢弃），由 [`internal/canvas/realtime.go`](../../../../backend/internal/canvas/realtime.go) 通过 Redis 分发给同画布的多实例 WebSocket 房间。

## 9. 资源身份、访问交付与方舟/姿势库

### 9.1 资源写入、签名分发与删除 Outbox

- **写入与幂等**：[`resource_store.go`](../../../../backend/internal/app/resource_store.go) 校验配额与 MIME 后先创建 `pending` 记录，写入本地磁盘或对象存储（OSS/COS）成功后更新为 `ready`，并按需异步生成视频播放副本或修复媒体宽高时长元数据（`media_probe.go` / `media_dimension_repair.go`）。成片保存失败时会透传准确的存储容量或额度不足原因。
- **分级访问交付**：[`resource_access.go`](../../../../backend/internal/app/resource_access.go) 与 `internal/assets/access.go` 将持久 `resourceId` 转换为短期签名访问描述（支持原图/原件受限导出、播放变体、Range 流式传输及供外部模型拉取的短期公开签名 URL）。
- **异步物理删除（Outbox）**：[`resource_delete.go`](../../../../backend/internal/app/resource_delete.go) 在普通删除时检查画布、短剧、任务等业务引用；确认可删后在同一数据库事务内移除业务记录并写入 `ResourceDeletionJob`，由后台 Worker 幂等清理底层存储对象。

### 9.2 方舟素材库（Schema 86）与画布姿势库

- **方舟素材库（[`ark_portraits.go`](../../../../backend/internal/app/ark_portraits.go)）**：管理真人（H5 活体认证 `LivenessFace`，带授权天数）、虚拟（AIGC）和版权 IP 三类素材组。用户建组先冻结积分，认证或建组成功才结算，失败/过期由 `ark_portrait_worker.go` 自动退回；H5 回调仅携带一次性随机 `state`，`BytedToken` 加密保存于服务端；任务中使用 `asset://` 引用时强校验归属、平台组授权范围与有效期。
- **画布姿势库（[`internal/poselibrary/`](../../../../backend/internal/poselibrary/catalog.go)）**：支持后台导入、同步与分类管理姿势资产；用户在画布选用姿势时，通过 `pose_library_bridge.go` 将平台姿势图复制为当前用户名下的独立 `Resource`，保证后续画布引用与删除计容边界清晰。

## 10. 身份认证、邮件日志与出站 SSRF 防护

- **认证与邮件/消费日报**：`internal/auth/`、`internal/emailidentity/` 与 `internal/emailtpl/` 统一处理密码/验证码/LinuxDo OAuth 登录、用户登录日志（Schema 53）、邮件发送日志及消费日报统计。
- **出站 SSRF 防护（[`internal/outbound/outbound.go`](../../../../backend/internal/outbound/outbound.go)）**：默认拒绝本机（loopback）、私网、链路本地、未指定与多播地址，并在拨号阶段二次校验解析后的真实 IP 及每次重定向目标。开发调试仅推荐通过 `CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS` 精确放行可信主机；自定义渠道中转（`/api/ai/custom`）强制要求 HTTPS（白名单除外）、禁止重定向且完全忽略遗留的全局私网开关。
