# Agent 运行机制、电商知识库与部署边界

本文基于当前代码树源码与部署编排，解析影策的两大智能体体系——**画布云端 Agent（小影，基于 Go 协调器 + Node Pi 运行时）** 与 **电商 Agent（小夜，基于五步策划状态机 + 离线行业知识库）**，以及生产环境六服务容器编排与宿主机在线更新器（Host Updater）的安全边界。

## 1. 画布云端 Agent：组成与重构后职责边界

云端 Agent 采用 **Go 业务治理层 + Node Pi 会话执行层** 双层架构：Node 进程仅负责上下文组织與推理循环，所有模型计费、画布读写、批量媒体生成、长期记忆与技能检索均通过 HTTP 桥接回到 Go 后端受控执行。

## 2. 会话主链与三条回调桥（`/model`、`/tool`、`/event`）

1. **创建与防重入**：浏览器调用 `POST /api/agent/runs` 或续轮接口；`startCloudAgentPi` 在 `piRunners` 映射中登记运行。若同一 `runID` 已有活跃进程则直接返回，防止恢复扫描与创建请求并发启动两个 Node 进程同时写同一份会话快照。
2. **冻结快照下发**：Go 读取数据库中的 `CloudAgentRun` 状态、语义 `Checkpoint` 与 `SessionJSONL`，编译本轮授权的平台工具 Schema 与技能目录，通过临时随机 Bearer Token 启动本地或远程 Node Pi 进程。
3. **三条受控回调**：
   - `POST /model`（[cloud_agent_pi_model.go](../../../../backend/internal/app/cloud_agent_pi_model.go)）：将 LLM 推理转换为平台内部 `cloud_agent_step` 任务，复用统一的渠道协议、思考等级、流式解析、错误分类与计费，并修正工具标签、强制工具选择与空回复，避免触发上游 Claude 400 错误。
   - `POST /tool`（[cloud_agent_pi_bridge.go](../../../../backend/internal/app/cloud_agent_pi_bridge.go)）：校验参数 Schema（若 Pi SDK 前置参数校验失败则转为 `tool_validation_failed` 事件推进游标）、工具可见性 `Scope`、资源归属与审批门禁。
   - `POST /event`（[cloud_agent_pi_events.go](../../../../backend/internal/app/cloud_agent_pi_events.go)）：Node 端通过 `eventChain` 串行提交消息、快照与上下文压缩事件；下一次 `/model` 或 `/tool` 必须等待前序事件落库。
4. **运行时隔离**：`agent-runtime.mjs` 强制设置 `projectTrusted: false` 且关闭 SDK 默认的 Shell、文件读写与外部目录扫描，仅暴露 Go 显式下发的 `customTools`。

### Embedded 与 Remote 双模式边界

| 维度 | 本地 Embedded 模式 | 生产 Remote 模式（`yingce-agent`） |
| --- | --- | --- |
| 触发条件 | `YINGCE_AGENT_URL` 为空 | `YINGCE_AGENT_URL` 非空（如 `http://yingce-agent:8081`） |
| 进程管理 | Go 后端直接 `exec` 本地 Node 子进程 | 独立容器 `yingce-agent` 维护内存排队与子进程池（默认并发 30，单进程 V8 堆上限 512 MB） |
| 回调监听 | `127.0.0.1:0` 动态端口 | `0.0.0.0:0`，向容器公布 `YINGCE_AGENT_BRIDGE_HOST=backend` |
| 故障处理 | 子进程退出后由 Go 收尾 | **远程调用失败绝不回退本地 Embedded**，防止已在远端执行的工具或扣费操作被重复执行 |

## 3. 29 项工具策略、单条/批量审批与恢复机制

### 3.1 五类工具与服务端 `Scope`

[tool/policy.go](../../../../backend/internal/agent/tool/policy.go) 与 [tool/registry.go](../../../../backend/internal/agent/tool/registry.go) 将全部 29 项工具划分为五类：

- `KindControl`：计划更新、向用户提问（选项卡片与末尾编号识别）、长期记忆读写（`memory_read` / `memory_update`）、技能市场检索与推荐（`skill_market_search` / `skill_recommend`）。
- `KindRead`：画布分页/焦点状态读取（`canvas_get_state` 等，绑定 `CacheCanvasRevision` 缓存）、生成前只读体检（`canvas_preflight`）、短剧上下文读取（`drama_get_context`）、技能文件渐进读取（`skill_search` / `skill_read_file`，支持中文 2-gram，仅允许读取 `.md`/`.txt`/`.json`）。
- `KindPrepare`：不修改画布且不收费的临时预览或视觉标注（如 3D 预演 `previs_preview`、审美批改视觉分析）。
- `KindWrite`：画布节点/连线增删改（`canvas_apply_ops`）、确定性制作看板生成（`canvas_build_board`）、短剧采用画布媒体（`drama_adopt_canvas_media`，标记 `AlwaysApprove: true`，即使自动模式也强制审批）。
- `KindMedia`：单条收费生成（`generate_media`）与批量收费生成（`generate_media_batch` / `media_batch_control`），**始终触发审批**。

### 3.2 暂停即退出，批准再续跑

当工具需要用户审批时：

1. Go 生成审批预览、锁定所需报价与参考资源租约，将运行状态写为 `waiting_approval` 并向前端推送 `approval_requested` 事件。
2. `/tool` 回调立即向 Node Pi 返回 `pause` 指令；Node 保存当前会话快照并**直接结束本轮子进程**，不会在等待人工点击期间长连接占用 Node 进程。
3. 用户调用 `POST /api/agent/runs/:id/approvals/:approvalId/decision`：
   - **拒绝（`reject`）**：运行直接进入 `rejected` 终态，不触发后续模型调用或扣费。
   - **批准（`approve`）**：若旧 Pi 进程仍在做退出前最后的快照刷新，`resumeCloudAgentPi` 会在 `piRunnerRestarts` 中登记重启标记，待旧进程完全退出后无缝拉起新会话，避免快速点击批准时恢复请求被去重逻辑吞掉。

### 3.3 批量生成（`generate_media_batch`）与 Canary 试跑

针对分镜多图或多段视频场景，[cloud_agent_media_batch.go](../../../../backend/internal/app/cloud_agent_media_batch.go) 支持单次审批最多 40 个占位节点：

- 批准后先向 Pi 写入占位文本 `"批次正在后台执行，完成后会把结果发给你。"`，由 Go 后台执行器按并发度（默认 3）逐条走完整的 `CreateTask` 准入与扣费。
- 若开启 `Canary`（试跑模式），首条生成完成后批次进入 `canary_done` 阶段并恢复 Agent 与用户确认风格，确认无误后再通过 `media_batch_control` 放行剩余条目并行出片。
- 每条任务完成即实时回写画布节点并触发前端入场动效（`agent-canvas-entrance.ts`）与进度条更新；整个阶段收尾后，再用真实批次结果回执替换占位文本恢复 Pi。

## 4. 长期记忆文档（Schema 76）与上下文检查点

- **用户长期记忆文档（`AgentMemoryDocument`）**：取代旧版零散经验表（旧 `agent_lesson` 接口仅保留兼容读取与导出，不再向 Agent 注入或启动后台压缩）。`memory_update` 支持整批增删改记忆条目：用户在设置中选择 `auto` 模式时经 `revision` CAS 直接生效并保留修订历史供一键撤销；选择 `review` 模式时写入待确认提案，在聊天面板渲染确认卡片。
- **三层会话状态**：
  1. `CloudAgentRun` 业务列与事件表（SSE 游标为递增事件 `seq`）；
  2. `SessionJSONL`（绑定 `expectedRevision` 条件更新，供 Node Pi 恢复 SDK 原生上下文）；
  3. 语义 `Checkpoint`（[`internal/agentcontext/checkpoint.go`](../../../../backend/internal/agentcontext/checkpoint.go)，严格限制 64 KiB、Schema v1，拒绝未知字段；`BuildPrompt` 强制声明历史摘要为不可信数据，防止从压缩摘要中伪造已批准计费指令）。

## 5. 电商 Agent（小夜）与行业知识库架构

电商工作区并非对画布 Agent 的简单换皮，而是一套面向商品视觉出品的受控流水线：

1. **离线知识包与启动强校验**：[`internal/ecommerceknowledge/`](../../../../backend/internal/ecommerceknowledge/bundle.go) 将行业视觉方法论打包在版本化 `bundle/` 中，服务端启动时通过 `EnsureBuiltinEcommerceKnowledge` 与 `EnsureIndustryTaxonomyKnowledge` 校验并入库，同时保留管理员本地自定义修改（`PreservedLocal`）。
2. **分类祖先路由与平台安全排版**：
   - [`internal/ecommercecatalog/`](../../../../backend/internal/ecommercecatalog/) 维护标准商品分类树（保留卫浴、护肤、家用电器等细分用途），知识检索严格限定在当前商品分类及其祖先链路内，避免跨品类串味。
   - [`internal/ecommerceagent/platform_knowledge.json`](../../../../backend/internal/ecommerceagent/platform_knowledge.json) 由前后端共用（构建前端镜像时显式复制），配合 `layout_safety.go`（8% 安全边距留白）与 `human_casting.go`（按目标市场轮换真实模特选角与肤质指导）生成合规视觉方案。
3. **五步策划与同商品记忆隔离**：围绕“商品资料 → 识图理解 → 风格方向推荐 → 逐屏方案审阅 → 批量生成（主图/详情页/拼长图）”，排除共享品牌 Logo 造成的跨商品错误串联，且拼长图默认仅拼接本轮生成作品。

## 6. 六服务生产部署与宿主机 Host Updater

### 6.1 `docker-compose.deploy.yml` 拓扑

生产环境标准编排包含六个服务，公网仅暴露 `web` 的 HTTP 端口（默认 `3000`）：

| 服务 | 镜像/组件 | 职责与网络隔离 |
| --- | --- | --- |
| `postgres` | `postgres:17-alpine` | 业务真机数据库，挂载 `postgres-data`，不向宿主机暴露端口 |
| `redis` | `redis:7.4-alpine` | 开启 AOF 每秒持久化，承担并发槽、限流与实时房间，不暴露宿主机端口 |
| `migrate` | 后端同镜像 `migrate-schema up` | 一次性 Schema 迁移容器，成功后退出，`backend` 依赖其 `service_completed_successfully` |
| `yingce-agent` | `open-ai-canvas-yingce-agent` | 远程 Pi 会话子进程池，无持久卷、无公网端口，通过内网回调 `backend` 动态端口 |
| `backend` | `open-ai-canvas-backend` | 核心 API、Worker 与协调器，挂载 `/data` 与 `/run/open-ai-canvas-updater` Socket |
| `web` | `open-ai-canvas-web`（Nginx） | 唯一公网入口，挂载 `web-data` 保留当前与上一版本 hashed chunk，防止旧标签页懒加载 404 |

[`nginx.conf`](../../../../nginx.conf) 精细区分代理策略：仅对 `/api/tasks/:id/text-events`、`/api/agent/runs/:id/events` 及明确的系统渠道流式路径关闭 `proxy_buffering` 与 `gzip`；对 `/api/canvas-projects/:id/realtime` 转发 WebSocket Upgrade；对 `/api/admin/ecommerce/skills/install` 放宽大包上传体积与超时；对 `/canvas`、`/assets`、`/welcome`、`/inspirations` 等同名静态目录与 React 路由做精确 `= /path` 回退 `index.html`，避免产生带容器内网端口的 301 重定向。

### 6.2 Host Updater 在线更新与自动回滚

业务容器不挂载高危的 `/var/run/docker.sock`，而是通过只读权限受控的 Unix Socket + Bearer Token 调用宿主机守护进程（[`internal/hostupdate/manager_ops.go`](../../../../backend/internal/hostupdate/manager_ops.go)）：

1. 校验 GitHub Release 清单、镜像 Digest 与 `SHA256SUMS` 签名。
2. 在停止旧服务后执行最终一致性数据库备份与环境快照（避免备份期间仍有尾流写入）。
3. 拉取固定 Digest 的新镜像，先行启动 `migrate` 验证数据库迁移，再切换 `yingce-agent`、`backend`、`web`。
4. 轮询健康检查与目标版本号；若任一步骤失败，自动恢复旧版 Compose 配置与数据库快照完成回退。
