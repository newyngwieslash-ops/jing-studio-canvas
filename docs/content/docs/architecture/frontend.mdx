# 前端架构与交互原理

本文基于当前代码树 `web/` 目录的实际源码，梳理影策前端从应用挂载、无限画布渲染、跨窗口实时协作、本地缓存隔离、生成任务消费到各创作工作台（短剧、电商、图片/视频工作台、3D 预演、时间线剪辑）的实现机制。依赖版本以 [web/package.json](../../../../web/package.json) 与锁文件为准。

## 1. 职责与分层边界

影策前端是基于 Vite 与 React 19 的单页应用（SPA），负责工作区导航、高频画布交互、多模态创作表单组装、账号级本地缓存降级以及任务与 Agent 事件流呈现。最终权限判定、模型路由、费用扣减与资源持久化均由 Go 后端兜底。

| 层次 | 目录与核心入口 | 核心职责 |
| --- | --- | --- |
| 启动与路由壳 | `application.tsx`、`router.tsx`、`layouts/user-layout.tsx` | 根挂载、全局主题/反馈/Query Provider、按需懒加载路由、右侧停靠面板让位与错误边界 |
| 页面编排层 | `pages/canvas/`、`pages/projects/`、`pages/ecommerce/`、`pages/workbench/`、`pages/create/` | 协调页面级工作流、组合业务 Hook、管理页面局部交互状态，不直接拼装底层 HTTP 信封 |
| 交互组件层 | `components/canvas/`、`components/editor/`、`components/model-picker.tsx` | 画布节点、视口手势、实时协作光标层、Live2D 形象、模型选择器与时间线面板 |
| 跨页状态层 | `stores/canvas/`、`stores/editor/`、`stores/use-*.ts` | Zustand 状态管理、持久化配置、有界撤销/重做历史（媒体大对象不进 `localStorage`） |
| 跨页副作用层 | `services/` | 云端同步与 Rebase、生成结果租约物化、画布实时 WebSocket、短剧/精修画布投送、插件宿主与诊断收集 |
| 协议与接口层 | `services/api/` | 统一 `http` 业务 JSON 解包、任务轮询与文本 SSE、自定义渠道中转、资源签名访问 |
| 纯算法与契约 | `lib/canvas/`、`lib/timeline/`、`lib/plugins/`、`lib/drama/`、`lib/model-pricing.ts` | 空间索引、LOD 与渲染预算、版本合并、提示词引用解析、编辑命令、价格换算与插件权限校验 |

React Query 负责服务端接口缓存，Zustand 负责工作区与编辑器状态，带用户 scope 的 `localforage` 负责画布、项目与素材等大 JSON 快照。三者各司其职，不能混用。

## 2. 启动顺序、会话恢复与路由守卫

[application.tsx](../../../../web/src/application.tsx) 渲染 `React.StrictMode → AppProviders → RouterProvider + AuthDialogHost`（登录弹窗挂载在路由树外，保证只读分享页等公开路由也能直接唤起登录）。

在 [app-providers.tsx](../../../../web/src/components/layout/app-providers.tsx) 中：

1. 外观与三层皮肤 Token（Primitive → Semantic → Component）率先写入根元素与文档元信息，避免首屏闪烁。
2. Ant Design `ConfigProvider` 注入统一主题与中文 locale，`AppFeedbackProvider` 提供全局反馈上下文，`QueryClientProvider` 挂载共享 [QueryClient](../../../../web/src/lib/query-client.ts)（默认 `staleTime` 为 30 秒，关闭窗口聚焦自动刷新与无差别自动重试）。
3. [AuthSessionHydrator](../../../../web/src/components/auth/auth-session-hydrator.tsx) 请求当前登录态并调用 `applyUserSession` 恢复对应账号的本地存储作用域；恢复完成前展示全屏加载壳，未登录或恢复失败则切入匿名 `guest` 作用域。
4. 已登录工作区挂载 `ClientRootInit`，清理 URL 中可能携带的敏感 `apiKey` 参数，初始化前端诊断缓冲，拉取服务端插件有效状态，并在后台静默刷新模型目录与姿势库缓存。

[router.tsx](../../../../web/src/router.tsx) 采用 `createBrowserRouter`：

- 认证页共用 `AuthScene`，公开分享页走 `/share/canvas/:token`，方舟活体认证回跳走 `/ark-portrait/result`。
- 主工作区由 `AuthenticatedWorkspaceLayout`（内含 `RequireAuth` 与 `UserLayout`）包裹；画布详情路由 `/canvas/:id` 在懒加载期间使用专属骨架 `CanvasRefreshShell`，减少白屏跳动。
- `RequireAuth`（配合 `isGuestWorkspacePath` 判断匿名可访问路径）与 `RequireFeature`（静态引入以避免懒加载导致整页回退全屏 Loader）仅作为前端导航体验边界，真实接口鉴权由后端逐请求执行。
- 开发专用实验室路由（`/dev/folders`、`/dev/previs-repro`）封装在 `devRoutes()` 函数体内：生产构建时 `import.meta.env.DEV` 为 `false`，Tree-shaking 会连同函数内的动态 `import()` 一起剔除，不会打入生产 chunk。

## 3. 无限画布：状态分层、大画布渲染与手势边界

### 3.1 持久快照与高频交互状态分离

[CanvasProject](../../../../web/src/stores/canvas/use-canvas-store.ts) 保存画布的完整结构：节点、连线、Agent 会话、外观设置、视口坐标、3D 预演场景、可选时间线，以及用于云端协同的 `revision` 与 `remoteContentHash`。

[project.tsx](../../../../web/src/pages/canvas/project.tsx) 是画布页的组合中心。它并不把每帧指针拖拽坐标直接写进全局 Zustand Store 触发全树重渲染，而是用页面级 React state 与最新 `ref` 承载高频交互，将生命周期、生成执行、选区拖拽、连线创建、图层拆解、短剧侧栏与 Agent 面板拆分为正交 Hook：

| 模块 | 入口文件 | 核心机制 |
| --- | --- | --- |
| 项目生命周期 | [use-canvas-project-lifecycle.ts](../../../../web/src/pages/canvas/use-canvas-project-lifecycle.ts) | 协调远端加载、本地 Rebase、自动保存、实时 WebSocket 连接与独立租约维护 |
| 视口与手势 | [canvas-viewport.tsx](../../../../web/src/components/canvas/canvas-viewport.tsx) | 平移、缩放、Pointer Capture、触控双指缩放与滚轮意图识别 |
| 选区与拖拽 | [use-canvas-selection-controller.ts](../../../../web/src/pages/canvas/use-canvas-selection-controller.ts) | 框选、多节点拖拽预览与落点坐标提交 |
| 连线控制器 | [use-canvas-connection-controller.ts](../../../../web/src/pages/canvas/use-canvas-connection-controller.ts) | 连线锚点命中、背板内部素材展开连线与兼容校验 |
| 渲染管线 | [use-canvas-render-model.ts](../../../../web/src/pages/canvas/use-canvas-render-model.ts) | 节点/连线索引、未变语义引用复用、视口裁剪与渲染预算 |
| 历史栈 | [use-canvas-history.ts](../../../../web/src/pages/canvas/use-canvas-history.ts) | 页面内撤销/重做及与 Agent 远端变更凭据的协调 |

### 3.2 空间索引、LOD 与渲染预算

当画布节点数量增长时，`useCanvasRenderModel` 依次通过四层纯算法控制 DOM 与媒体开销：

1. [canvas-spatial-index.ts](../../../../web/src/lib/canvas/canvas-spatial-index.ts)：建立节点包围盒空间索引，快速查询当前视口矩形命中的候选节点。
2. [canvas-node-visibility.ts](../../../../web/src/lib/canvas/canvas-node-visibility.ts)：结合连线关联与选中态筛选可见集合，复用语义未发生变化的节点对象引用以跳过子组件重渲染。
3. [canvas-node-lod.ts](../../../../web/src/lib/canvas/canvas-node-lod.ts)：按缩放比例（zoom）切换细节层级（LOD），远景下简化富文本控件与次要装饰。
4. [canvas-render-budget.ts](../../../../web/src/lib/canvas/canvas-render-budget.ts)：限制同屏同时挂载的高开销媒体元素（如高分辨率原图或视频解码器）数量。

### 3.3 指针捕获与滚轮隔离边界

`CanvasViewport` 使用 `setPointerCapture` 保证指针移出画布边界时拖拽与框选仍能可靠收尾；滚轮事件采用非 passive 的 capture 监听以区分“画布缩放/平移”与“浮层内部滚动”。事件忽略选择器显式覆盖 `data-canvas-no-zoom`、`data-canvas-wheel-scroll` 以及 Modal、Popover、Dropdown、Select、提示词编辑器等浮层。任何新增画布内嵌滚动面板都必须声明上述属性，防止滚动长文本时误触画布缩放。

### 3.4 画布实时协作与非 React 光标渲染

多窗口或多人打开同一画布时：

- [canvas-realtime-client.ts](../../../../web/src/services/canvas-realtime-client.ts) 与 [canvas-realtime.ts](../../../../web/src/services/canvas-realtime.ts) 按账号与画布 ID 复用 WebSocket 连接（`/api/canvas-projects/:id/realtime`），对高频光标/拖拽广播做节流合并并支持断线重连。
- [canvas-collaboration-layer.tsx](../../../../web/src/components/canvas/canvas-collaboration-layer.tsx) 感知房间在线设备数：仅一个窗口在线时自动停止采集本地指针事件以节省开销。
- [canvas-presence-renderer.ts](../../../../web/src/components/canvas/canvas-presence-renderer.ts) 采用 `requestAnimationFrame` 直接复用和移动 DOM 节点来投影远端光标与拖拽虚框，**高频坐标不进入 React State**，避免远端鼠标移动引发整张画布重渲染。

## 4. 本地缓存、账号切换隔离与云端 Rebase

### 4.1 三层保存状态区分

[localforage-storage.ts](../../../../web/src/lib/localforage-storage.ts) 与 [user-scope.ts](../../../../web/src/lib/user-scope.ts) 将所有本地存储键按 `name:user:<scope>` 隔离（未登录为 `guest`，已登录为用户 ID）。

前端严格区分三种状态：**页面内存态** → **本机 `localforage` 落盘态** → **服务端已确认版本（`revision`）**。[CanvasSyncStatus](../../../../web/src/pages/canvas/canvas-sync-status.tsx) 仅在远端同步状态为 `done` 且无未提交 journal 或网络错误时才展示“已同步”；后端不可用时的本地缓存成功只代表本机降级保存，不冒充云端已持久化。

### 4.2 账号切换的六步排空与隔离

单纯修改存储键前缀不足以阻止切换瞬间的在途异步写入串号。[user-session.ts](../../../../web/src/lib/user-session.ts) 的 `applyUserSession` 与 `switchUserStorageScope` 按严格顺序执行：

1. 身份变更时立即清空共享 `QueryClient`，丢弃旧账号接口缓存。
2. 调用 [generation-consumer-lifecycle.ts](../../../../web/src/services/generation-consumer-lifecycle.ts) 暂停生成结果消费，中断并等待所有在途物化协程退出。
3. 进入远端同步独占区，将旧账号待保存画布与素材 flush 完毕，清理资源签名 URL 缓存与内存 Blob URL，再切换当前 user scope。
4. 在禁止持久化的保护边界内重置各 Zustand Store 的内存态，写入新会话身份。
5. 从新 scope 的 `localforage` 重新 rehydrate 各 Store（若新账号无本地快照则显式初始化为空）。
6. 重建远端同步基线并递增 session generation 令牌，任何迟到的旧会话异步回调都会因令牌失配被丢弃。

### 4.3 版本号、Mutation Journal 与冲突保护

[user-data-sync.ts](../../../../web/src/services/user-data-sync.ts) 维护已确认基线、待提交变更日志（mutation journal）与串行同步链：

- `loadCanvasProjectForEditing` 拉取远端画布后，对比远端 `revision`、本地内容哈希与已确认基线；若本机存在未上传修改，则在远端新基线上执行 rebase 合并，而不是用服务端快照粗暴覆盖用户未确认编辑。
- `applyAgentCanvasPatches` 处理云端 Agent 推送的画布增量：严格校验 `revision = baseRevision + 1`；若发现版本号断档则触发完整重读，必要时生成本地冲突备份画布以保护用户手改内容。
- Agent 的画布写入附带 `canvas_updated.undo` 凭据，前端通过 [agent-canvas-undo.ts](../../../../web/src/lib/canvas/agent-canvas-undo.ts) 校验原运行 ID 与画布哈希后调用后端接口执行逐步幂等撤销。

## 5. API 通信合同与模型渠道中转

### 5.1 统一 `http` 业务信封解包

[request.ts](../../../../web/src/services/api/request.ts) 导出的 `http` 是调用后端业务 JSON 接口的唯一入口（共享 `apiClient`，默认 `baseURL: "/api"`，`withCredentials: true`）：

- 后端业务成功固定为 `{ code: 0, data: T, msg: string }`；即使 HTTP 状态码为 200，只要 `code !== 0`，`request()` 就会抛出结构化 `ApiError`（携带 `status`、`code`、`reason`、`details`、`retryable`、`retryAfterMs`）。
- 业务模块与 React Query 直接消费解包后的 `T`，通过 `ApiError.reason` 或错误码分支处理异常，禁止靠正则解析中文 `msg`。
- 主动取消的请求统一保留为 `DOMException("AbortError")`，避免路由切换中断请求时弹出错误提示。二进制导出（如支付 CSV、诊断包 ZIP）使用 `http.raw`。

### 5.2 自定义渠道安全中转

浏览器直连自定义模型渠道在 [custom-channel-relay.ts](../../../../web/src/services/api/custom-channel-relay.ts) 与 [channel-transport.ts](../../../../web/src/services/api/channel-transport.ts) 中收敛：所有第三方自定义渠道请求均改写为向登录态后端 `/api/ai/custom` 发起，由请求头携带目标上游信息，并在组装时主动剥离旧的 `X-Canvas-Upstream-Headers` 与 `x-goog-api-key`，不在浏览器 URL 中暴露任何第三方密钥。

## 6. 生成任务执行、SSE 流与幂等物化

### 6.1 提交、引用水合与监听边界

[useCanvasGenerationExecutor](../../../../web/src/pages/canvas/use-canvas-generation-executor.ts) 收集节点提示词、连接引用、模型能力档位（包括图生图默认跟随参考图比例 `canvas-reference-image-size.ts`、方舟 `asset://` 引用改写 `canvas-node-generation.ts`、思考等级 `thinkingLevel`），将本机 Blob/Data URL 先上传转换为后端 `Resource` 引用后，交由 [generation-task.ts](../../../../web/src/services/api/generation-task.ts) 创建任务。

`waitForGenerationTask` 默认每 2 秒轮询一次任务状态；注意**传入等待器的 `AbortSignal` 仅用于停止当前页面的等待循环，不会向后端发送取消任务指令**（页面刷新或离开后后台生成继续进行；显式中止需调用 `cancelGenerationTask`）。生成完成时支持标签页标题闪烁、动效与提示音提醒。

### 6.2 文本任务 SSE 增量流

当任务启用流式文本时，前端通过带 Cookie 的 `fetch` 订阅 `GET /api/tasks/:id/text-events`。[task-text-stream.ts](../../../../web/src/services/api/task-text-stream.ts) 按双换行解析标准 SSE 帧，以递增数字 `sequence`（事件 `id`）去重，断线重连时携带 `?after=<lastEventId>`。收到 `terminal` 事件后仍会回读一次权威任务记录以确认最终状态与产出。

### 6.3 租约 Fence 与结果物化（Materializer）

后端任务 `status === "succeeded"` 仅代表上游生成与服务端回存完成，不代表前端素材库登记和画布节点写回已经落盘。[generation-task-materializer.ts](../../../../web/src/services/generation-task-materializer.ts) 与 [canvas-generation-consumer.ts](../../../../web/src/services/canvas-generation-consumer.ts) 通过持久化 effect 租约保证前端交付幂等：

- 为每项副作用派生确定性键：`materialize:<taskId>:<outputIndex>`、`attach-node:<taskId>:<nodeId>:<outputIndex>`、`attach-message:<taskId>:<messageId>:<outputIndex>`、`agent-resume:<taskId>:<continuationId>`。
- 消费者先 `claim` 领取带 `fence` 的租约并每 10 秒 `renew` 续租；若其他标签页或消费者已持有租约则等待，已完成则直接复用 `materializedAssetId`。
- 只有素材登记 flush 成功且画布节点合并落盘后，才调用 `complete` 标记完成；若落盘失败则抛出 `CanvasGenerationDurableAckError` 并在下次恢复时重试，避免生成成功却丢节点。
- 生成成功时按 [produced-model.ts](../../../../web/src/lib/canvas/produced-model.ts) 冻结节点实际产出模型快照，后续用户切换下拉框选用模型不会篡改历史产物的模型角标。

## 7. 专项创作工作台、3D 预演与时间线插件

### 7.1 图片/视频工作台、AI 拆图与姿势库

- **图片/视频工作台（`/toolbox/image`、`/toolbox/video`）**：由 [image-workbench-page.tsx](../../../../web/src/pages/workbench/image-workbench-page.tsx) 编排出品模板、参考图、批量提交与按 `batchId` 归组的画廊视图（`workbench-batches.ts`）。
- **AI 拆图工作流**：由 [use-canvas-media-tools.ts](../../../../web/src/pages/canvas/use-canvas-media-tools.ts) 与 `canvas-image-layer-*.ts` 驱动，先请求视觉规划拆解前景/主体/背景图层，再并行生成透明 PNG 图层组并支持一键合成为素材。
- **画布姿势库**：通过 [canvas-pose-library-modal.tsx](../../../../web/src/components/canvas/canvas-pose-library-modal.tsx) 浏览 3D/人体姿势模板，选用时经后端桥接复制为用户自有 `Resource` 并插入画布节点。

### 7.2 电商五步工作区与短剧制作台

- **电商工作区（`/ecommerce`）**：在 `pages/ecommerce/` 下实现商品资料录入、AI 识图理解、创意方向选择、逐屏方案审阅与批量出图五步状态机（`flow.ts`），会话持久化由 [ecommerce-session.ts](../../../../web/src/services/ecommerce-session.ts) 管理，报价统一复用 [model-pricing.ts](../../../../web/src/lib/model-pricing.ts) 的 `systemModelQuoteRequest`。
- **短剧制作台（`/projects/:id`）**：在 `pages/projects/studio/` 下提供剧本对照、角色/场景设定锁定（含角色差异化外貌重写）、剧情段（`DramaSegment`）分镜卡片、单段时长配置（新建页支持 4–15 秒快捷选择）、剪映草稿流式 ZIP 导出导入，以及一键投送到精修画布（`drama-canvas-projection.ts`）。

### 7.3 3D 预演台与时间线编辑器插件边界

- **3D 预演台**：从画布镜头节点打开，支持场景摆件、角色姿态、A/B 点移动关键帧、机位时间轴编排，并导出构图截图、白模视频与深度图作为生成参考。
- **时间线命令状态机**：[editor-store.ts](../../../../web/src/stores/editor/editor-store.ts) 要求所有时间线修改必须通过可序列化命令（`editor-commands.ts`）执行，拖拽手势通过 `previewGesture → commitGesture/cancelGesture` 合并为单条有界快照历史，防抖 1.5 秒串行保存。
- **插件 v2 与双导出路径并存**：[editor-shell.tsx](../../../../web/src/lib/plugins/builtin/editor/editor-shell.tsx) 作为内建 `yingce.plugin/v2` 插件一次性注册时间线、预览、检查器、素材、字幕、转写、导出、AI 助手 8 个插槽，由 [plugin-permission-check.ts](../../../../web/src/lib/plugins/plugin-permission-check.ts) 强校验 `timeline.read`、`timeline.command`、`export.run`、`ai.text` 等权限。注意当前编辑器插件面板支持提交后端渲染任务（默认）与显式本地 `ffmpeg.wasm` 导出，而画布旧版时间线弹窗 [CanvasTimelineDialog](../../../../web/src/components/canvas/canvas-timeline-dialog.tsx) 仍直接调用浏览器端合成，排障时需先确认触发入口。

## 8. 常见现象排障与回归测试入口

| 现象 | 优先检查位置 | 常见误判 |
| --- | --- | --- |
| 工作区首屏慢或切号卡顿 | `AuthSessionHydrator`、旧 scope flush 等待、远端基线拉取 | 误以为只是组件渲染慢而盲目加 `useMemo` |
| 刷新后画布改动丢失或回退 | `localforage` 落盘、mutation journal、远端 `revision` 冲突备份 | 误把内存 Store 更新当作服务端已确认保存 |
| 任务显示成功但画布未出图 | `generation-task-materializer.ts` 租约状态、`CanvasGenerationDurableAckError` | 误以为模型未生成而引导用户重新扣费提交 |
| 离开页面后任务仍在扣费执行 | 监听 `AbortSignal` 与显式取消接口 `cancelGenerationTask` 的区别 | 误以为组件卸载 abort 轮询就会自动取消后端任务 |
| 多人在线时画布掉帧 | 检查是否有新增逻辑把实时坐标写进了 React State 而非 `canvas-presence-renderer.ts` | 误判为 WebSocket 传输本身过慢 |
